# Text Adventure with LLM-Engine Fusion

> 一个 **LLM（大语言模型）与游戏引擎深度融合** 的结构化工程项目，用 Pygame 实现的一个文字冒险游戏原型。

本项目由**本科生基于兴趣开发**，用于积累完整的工程项目经验。核心亮点不是游戏玩法本身，而是探索如何把 **大模型当作游戏的内容生成引擎**，并与**确定性的数值/规则引擎**可靠地融合在一起——涉及自然语言解析、结构化输出校验、数据流设计、容错与日志等多个工程问题。

---

## 项目定位

- **形态**：文字冒险游戏（PyGame + 回合制战斗 + 7 关推进）
- **核心命题**：*"如何让 LLM 生成的内容既能带来随机性/趣味性，又不破坏游戏数值平衡与确定性？"*
- **双模式**：完全确定性的**离线模式**（纯规则引擎）+ 调用大模型的 **AI 设计模式**

游戏的具体玩法、规则、被动技能语法等细节，请见 [**instruction.md**](./instruction.md)。本文档聚焦项目**架构、设计决策与工程实现**。

## 核心设计：LLM 与游戏引擎的融合

整个系统围绕一条清晰的数据流组织：

```
玩家自由设计角色（属性 + 自然语言被动）
        │
        ▼
┌─ 离线模式 ──────────────────────────────┐
│  规则经济系统生成敌人（预算/波数/强化）      │
│  被动从「玩家被动怪物化」+「系统被动池」抽取  │
└────────────────────────────────────────┘
        │
┌─ AI 模式 ───────────────────────────────┐
│  大模型按结构化 Prompt 生成敌人 JSON      │
│  输出经 JSON 解析 + 合法性过滤 + 数值校验   │
│  第 7 关可参考前 6 场战斗记录针对性布置      │
└────────────────────────────────────────┘
        │
        ▼
   战斗引擎（确定性数值结算）
        │
        ▼
   战斗日志记录 → 通关结算报告 / 死亡报告
```

### 关键工程点

**1. 自然语言被动技能的「解析器」而非「规则匹配」**

`game/passive_engine.py` 是一个**两层解析器**：

- **条件层（Condition）**：从自然语言提取触发时机（回合/攻击/受击/死亡…）、概率、生命阈值、回合数等条件
- **效果层（Effect）**：把效果文本解析为结构化数值（攻击力提升 N 点 / 生命上限的 X%…）

这样玩家（或 AI）可以用**自然语言**描述技能，系统再**解析为确定性的数值逻辑**去执行，而不是靠硬编码关键词匹配。它天然是「让 LLM 自由表达、让引擎确定性落地」的关键桥梁。

**2. LLM 生成 → 结构化校验 → 落地**

AI 模式并不信任模型输出的原始文本，而是走完整校验链：

- 严格 `SYSTEM_PROMPT` 约束：限定合法属性字段、合法被动时机/效果、禁止跨单位联动
- 生成结果按 OpenAI Chat Completions 格式解析 JSON
- **后处理过滤**：剔除含「传给下一个/队友」等无效联动写法的被动
- **数值平衡提示**：把玩家的战斗力指标（DPS / 有效生命）注入 Prompt，引导 AI 在合理区间设计怪物

**3. 容错与可观测性**

- 被动解析失败在战斗中**显式提示"未生效"**，绝不静默忽略
- 每次 AI 调用错误写入 `api_log.txt`（启动时清空），含状态码、原始响应与排查建议
- 每次战斗自动记录完整日志，用于第 7 关 AI 参考与通关结算报告

## 技术架构

```
game/
├── character.py        # 角色框架 / 属性分类 / 全局关卡配置
├── enemy.py            # 怪物类型模板与生成
├── passive_engine.py   # ★ 自然语言被动解析器（条件层 + 效果层）
├── battle.py           # ★ 确定性战斗引擎（伤害公式 + 被动触发 + 死亡结算）
├── level.py            # 关卡经济系统（预算 / 波数 / 强化 / 治疗）
├── run.py              # 整局会话状态机（7 关推进 + 战斗历史）
├── ai_design.py        # ★ LLM 接入层（Prompt 构造 / JSON 解析 / 校验过滤 / 日志）
├── passive_pool.py     # 敌方被动池配置读写
└── ui.py               # Pygame 界面 / 菜单 / 积木式被动编辑器 / 结算画面
```

### 模块职责边界

| 模块 | 职责 | 关键设计 |
|------|------|---------|
| `passive_engine` | 把自然语言技能解析为结构化数据 | 条件层 / 效果层两层分离，可组合 |
| `battle` | 确定性战斗结算 | 纯函数式伤害公式，被动按时机触发 |
| `level` | 经济/难度曲线 | 一切加法、拒绝指数，预算驱动 |
| `ai_design` | LLM 内容生成 | 结构化 Prompt + JSON 解析 + 过滤校验 + 日志 |
| `run` | 状态机 | 关卡推进、战斗历史、通关结算数据 |

### 技术栈

- **Python 3.10+**
- **Pygame**：UI 与交互
- **requests**：调用 OpenAI 兼容的 LLM API

## 安装与运行

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 准备配置
cp config/settings.example.json config/settings.json
#    编辑 config/settings.json，填入你的 API Key（仅 AI 模式需要）

# 3. 运行
python main.py
```

> 支持任意兼容 **OpenAI Chat Completions 协议**的服务（OpenAI、DeepSeek、通义、本地 Ollama 等），只需修改 `config/settings.json` 的 `base_url` 与 `model`。

## 为什么值得一看（对本科生项目）

本项目刻意覆盖了一个**真实软件工程**会遇到的多个问题域：

1. **解析器设计**：如何把不严格的自然语言输入，安全地转成严格的结构化逻辑（被动解析器）
2. **LLM 集成工程**：不只是"调个 API"，而是处理 Prompt 工程、结构化输出、JSON 容错、非法内容过滤、失败重试与日志
3. **确定性 + 随机性平衡**：离线规则引擎 vs AI 生成的取舍与融合
4. **状态机与数据流**：7 关推进、战斗历史、跨模块数据传递
5. **可观测性**：运行日志、错误定位、战斗报告
6. **工程卫生**：`.gitignore` 排除敏感配置、`settings.example.json` 模板、README/文档分离
